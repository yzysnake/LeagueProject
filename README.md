# LoL 职业赛 BP 后胜率预测

BP（ban/pick）结束、开赛前，给出蓝方获胜概率。覆盖 tier-1 全部赛区与国际赛事。
完全本地部署，离线可用。

## 效果

| | log loss | Brier | AUC | accuracy |
|---|---|---|---|---|
| walk-forward 样本外（23,060 场） | 0.61917 | 0.21543 | 0.7107 | 0.6525 |
| **final holdout（989 场，一次性揭盲）** | **0.61653** | 0.21457 | 0.6992 | 0.6532 |
| 对照：Polymarket 市场（1,302 场交集） | 0.62748 | 0.21875 | 0.6992 | 0.6598 |

两点值得注意：

- **holdout 与开发期几乎一致**（差 0.0026，门槛 0.02），说明模型选择过程本身没有过拟合。
- **与真金白银的预测市场统计上无法区分**（ΔBrier +0.00076，远低于 MDE）。

## 主要结论是一个负结果

预注册第一天就写好并允许为负的那条，现已兑现：

> **BP 阶段本身（协同、克制、选手熟练度）在职业赛的数据量下贡献不可测量。**
> 可预测的部分几乎全部来自队伍与选手实力。

| 加入的东西 | ΔlogLoss | 超过 MDE |
|---|---|---|
| 队伍实力 | +0.0577 | ✓ |
| 分层 BT 选手潜变量（替代 Elo） | +0.0143 | ✓ |
| 英雄版本强度 | +0.0015 | ✓（边缘） |
| 选手熟练度 | +0.0004 | ✗ |
| 协同 + 克制 | −0.0004 | ✗ |

## 快速开始

零凭证即可跑通主链路（数据源全部匿名可得）。

```bash
make setup      # uv sync --frozen，Python 3.11
make data       # 下载 OE 2014-2026 共 13 个 CSV（约 700 MB）+ 五重校验
make bronze     # → Parquet，物理丢弃 135 个赛后统计列
make silver     # → 一场一行的建模宽表
make icons      # 173 张英雄图标 + 中文名 + 现役战队队标，供离线 UI 使用
make artifact   # 训练生产模型（约 40 分钟，分层 BT 要全量拟合）
make refresh    # 只重解实力快照（silver + 盯盘台账的新赛果，几秒）；盯盘每有新赛果会自动做
make app        # 启动本地站点
```

其余命令：`make test` / `make lint` / `make gate` / `make monitor` / `make reproduce` / `make backfill`。

### 前后端拆分部署

```bash
make api          # 只起 FastAPI（127.0.0.1:8000，单 worker）
make up           # docker compose：api + web，**纯离线即可用**
make up-online    # 额外起每日拉数与实时轮询
```

七个端点：`/health` `/champions` `/players` `/predict` `/predict/batch`
`/explain` `/live`。实测单次 `/predict` 中位 **0.5 ms**（p99 0.7 ms），
`/predict/batch` 遍历 173 个英雄 3 ms。

三条写进 compose 的硬约束：

- **`--workers 1`**：artifact 含状态快照（2,070 队 / 10,863 选手 /
  113,058 条选手英雄计数），每 worker 一份，多 worker 内存线性翻倍。
  横向扩要加容器实例，不是加 worker。
- **只绑 `127.0.0.1`**：不对外暴露。
- **`profiles: ["online"]`**：让「离线降级」成为默认状态，
  而不是一条需要额外实现和测试的路径。

**可选**（不影响主链路）：注册免费 Fandom 账号可用 Leaguepedia 补充源；
加入 OE Discord 可获知 schema 变更预警。详见 `docs/PLAN.md` §7.11。

## 网站六个页面

顶部导航的多页站点（`make app`），深色主题，完全离线：英雄头像、中文名、战队队标都在 build 时落盘。
打开时有一段海克斯科技风格的开场（约 2 秒，同时就是首轮载入的加载页）：每个浏览器会话只放一次，
12 小时内再开只放约 1 秒的短版，点击或按任意键跳过，系统开了「减少动态效果」时不放动画。

| 页面 | 做什么 |
|---|---|
| **阵容模拟** | 选赛事和两支队，**点头像选英雄**（按位置筛、中英文 / 称号搜索、键盘回车选中、已选的变灰），**每个位置可换选手**（该队最近一年在这个位置上场过的人，附实力排位与场次），胜率实时更新并拆成「实力 / 阵容 / 赛况」 |
| What-if | 换任一位置的英雄，看胜率往哪边动、动多少，一键把换法写回阵容模拟 |
| **实时比赛** | 自动发现正在进行的职业比赛，读 BP 后的阵容并给出胜率 |
| 近期战绩 | 盯盘落盘的预测 vs 赛后结果：命中率 / log loss / Brier，区分实时与赛后补录 |
| 历史回看 | 拿真实比赛复盘，可按赛事 / 战队筛 |
| 模型说明 | 模型卡：怎么算的、准到什么程度、哪里别全信 |

阵容模拟的几个约定：

- **一个位置可以有多名选手**。名单来自该队最近一年的出场（现役 80 支队里 72 支至少一个位置有替补或轮换），
  默认是该队最近一场的首发。「前 x%」是分层 BT 实力在全部已知选手里的排位，「新人」= 模型没见过，按队伍平均计。
- 没选的英雄按该位置的平均版本强度计，所以一个英雄都不选时看到的就是两队的纯实力对比。
- 赛事只影响蓝方先验；跨赛区对阵（Worlds、MSI）选国际赛事即可，两边可以是任意赛区的队。
- 阵容板是 Streamlit components v2 的自定义组件（`src/lolwp/app/board.py`），无需前端构建步骤。

实时页的设计要点：

- **唯一权威的开赛信号是 livestats 的 204→200 跳变**，不是赛程接口的 `state`。
  实测赛程标 `inProgress` 时比赛未必已开打——它标的是「局间休息 + BP 开始」。
- 六种对局状态各有明确文案，**接口挂掉只降级本页**，手动摆阵容完全不受影响。
- 实测：从 livestats 首次返回 200 到页面出概率 **0.221 秒**。

## 模型

> **生产模型是揭盲之后用全量数据重训的版本**（预注册修订 A4）：同一规格，训练截止从 2026-05-31
> 延到最新数据。上面的 walk-forward 与 holdout 成绩属于揭盲时评测的、训练截至 5/31 的模型；
> 重训模型的样本外成绩看站点「近期战绩」里它训练截止日之后的预测。`--scope dev` 可重建评测时的模型。
>
> **实力快照不冻结**：外层系数随重训更新，分层 BT 快照则每有新赛果就重解（盯盘对账后自动 `make refresh`，
> 数据 = silver + 台账里 OE 还没收录的局）。快照冻结一个月 log loss 就差 0.012，
> 见 `reports/exp_model_improvements.md`。站点页脚的「实力更新至」就是它。

**BT4_LR** = 按赛区收缩的 side 先验 + 分层 Bradley-Terry 三项（选手潜变量 /
chemistry / 赛区校准）+ 两层经验贝叶斯的英雄版本强度，外层普通 L2 logistic。

标准化系数：选手潜变量 0.840，英雄版本强度 0.121，chemistry 0.020，
赛区 0.012，side 先验 0.014。

阶段 8 跑了 7 个候选（含 CatBoost、zero-init DeepSet、两种集成），
**无一在 MDE 之上胜过它**。

## 这个项目真正的技术含量在评估协议

网上同类项目大多败在这里。本项目做了：

- **series 级分组切分 + 7 天 embargo**，90 折 rolling-origin walk-forward。
- **四个负控制进 CI**：标签打乱回到 0.6921 / 未来删除不变性 bit-identical /
  泄漏探针 AUC +0.298 / 同版本两次 bit-identical。
- **每个比较各自测组内相关**，MDE 主判据用 series 级 block bootstrap。
- **预注册 + 三条公开修订**（A1/A2/A3），holdout 一次性揭盲。

### 三次撞上同一个坑，值得单独写下来

阈值按全样本尺度定、却拿去判小样本，会得到一个永远在报警的告警器：

| 判据 | 误报率 | 处理 |
|---|---|---|
| 预注册红线「任一 fold AUC > 0.78」 | 零信号下 63% | 修订 A3 换成合并 AUC |
| 预注册「ECE ≤ 0.03」 | 989 场上 98% 过不了 | 揭盲前已记录，报告中说明 |
| 监控「reliability > 3×基线」 | 23/23 窗口全报警 | 阈值改由抽样分布推出 |

现在所有阈值都从抽样分布推出，健康模型的误报率等于 1−q。

## 被搁置假设的自动重测

本项目有一批假设是**「现在测不出来」而非「已被证伪」**，两者的处理完全不同。
`reports/retest_ledger.jsonl` 是 append-only 的台账，记录每次重测的结果，
**趋势比单次结论重要**。

```bash
make retest          # 重跑全部，追加进台账
make retest-history  # 只看历史趋势
make install-launchd # 【推荐】装年度自动重测（每年 1 月 5 日）
make install-cron    # 备选：cron 版
```

**年度任务用 launchd 不用 cron**：cron 在机器睡眠时**不补跑**，
错过就得再等一年；launchd 的 `StartCalendarInterval` 会在唤醒后补跑一次。
对每年只跑一次的任务，这个差别是决定性的。

当前基线（2026-09-21）：

| 假设 | 统计量 | 门槛 | 余量 |
|---|---|---|---|
| BO 内比分差 | 0.00073 | 0.00084 | **0.87×** |
| 英雄协同可靠性 | 0.1754 | 0.20 | 0.88× |
| 英雄克制可靠性 | 0.1566 | 0.20 | 0.78× |
| 选手熟练度 | 0.00009 | 0.00064 | 0.14× |

克制的可靠性学习曲线**还在爬**（12k→0.087, 24k→0.119, 48k→0.151, 96k→0.180），
对数外推需约 15 万场职业比赛，现有 10.2 万——**再等几年它自己就会越线**。
有台账才不会忘了回来看。

某个假设一旦越过门禁，`tests/test_backlog.py` 会让测试变红，
强制人工评估要不要加进生产模型。
