## 1. 做了什么

一个可本地部署的英雄联盟职业比赛胜率预测系统：BP 结束、开赛前，
输入双方阵容与选手，输出蓝方获胜概率。覆盖 tier-1 全部赛区与国际赛事。

- **数据**：Oracle's Elixir 2014–2026 共 102,084 场，全部匿名免费获取。
- **模型**：分层 Bradley-Terry 选手潜变量 + 按赛区收缩的 side 先验
  + 两层经验贝叶斯的英雄版本强度，外层 L2 logistic。
- **产品**：Streamlit 本地站点，手动摆阵容 / what-if 敏感度 / 历史回看，
  完全离线可用；实时读取正在进行的比赛已端到端跑通。

## 2. 最重要的三个结论

### 2.1 实力层是几乎全部的信号，BP 阶段的贡献不可测量

这是本项目的主要结论，也是预注册里提前写好、允许为负的那一条。

| 加入的东西 | ΔlogLoss | 是否超过 MDE |
|---|---|---|
| 队伍实力（Elo） | **+0.0577** | ✓ |
| 分层 BT 选手潜变量（替代 Elo） | **+0.0143** | ✓ |
| 英雄版本强度 | +0.0015 | ✓（边缘） |
| 选手熟练度 | +0.0004 | ✗ |
| **协同 + 克制（冻结迁移）** | **−0.0004** | **✗** |

α̂_synergy = +0.079 [−0.035, +0.129]，α̂_counter = +0.094 [+0.025, +0.125]，
方向稳定（94%/98% 同号）但联合样本外增量为负。

**「BP 阶段在职业赛数据量下贡献不可测量」是结果，不是失败。**

### 2.2 与真金白银的预测市场统计上无法区分

Polymarket 交集 1,302 场（2025-10 起）：

| | log loss | Brier | accuracy |
|---|---|---|---|
| Polymarket 市场 | 0.62748 | 0.21875 | 0.6598 |
| BT4_LR | 0.62522 | 0.21798 | 0.6521 |

ΔBrier +0.00076，落在预期区间 [−0.015, +0.015]，ΔlogLoss 远低于 MDE。
不是可疑地更好（那要查泄漏），也不是明显更差。

市场 accuracy 更高而 log loss 更差：**市场更擅长押对边，模型更擅长给对概率。**

## 3. 方法论上最值得记住的六条

1. **ICC 不是数据集常数，而且 ANOVA 版在异方差下严重高估。**
   本项目 48.8% 的 series 是单局，单局 var(d) 是多局的 2.04 倍；
   真 ρ=0 的数据在这种异方差下会被报成 ICC 0.445。改用只取多元素组内真实配对的
   稳健估计后，L2→L3 的 ρ 从 0.312 降到 0.0266。

2. **MDE 的主判据用 bootstrap，不用参数化 deff。**
   参数化路线的偏差方向会随 ρ 估计器翻面：ANOVA 版给 √deff 1.129（过度保守），
   稳健版给 1.012（不够保守），而经验 bootstrap 是 1.042。

3. **可靠性是必要条件不是充分条件。**
   选手×英雄胜率的 split-half 可靠性最高（0.444，稳定通过闸门），
   而它对模型的增量是 +0.0004，低于 MDE。它可靠是因为强选手用什么英雄都赢。

4. **α̂ 的符号一致性不能单独作为裁决依据。**
   朴素两阶段拟合下 α̂ 在 90 折里 100% 同号、系数大 8 倍，
   而样本外 log loss 从 0.631 涨到 0.997。是校准斜率塌到 0.091 当场拆穿的。

5. **判断校准漂移看斜率，不看 ECE。**
   ECE 有系统性正偏且随样本缩小而增大：全样本 0.0105 的模型，
   在 1,302 场的子集上期望值就是 0.0402。

6. **红线判据本身要先验证。**
   预注册的「任一 fold AUC > 0.78」在 90 折 + 小验证窗下，
   零信号时误报率 63%，健康模型误报率 38%。
   一条 38% 时间在报警的告警器等于没有告警器。已替换为合并 AUC + 模拟参照分位。

## 5. 工程上必须记住的坑

- **`year` 是赛季年不是日历年**，2,709 场不一致且双向。按 year 切时间会静默泄漏。
- **`datacompleteness == 'complete'` 过滤会删掉 LPL 2022–2025 全部四年**（100% partial）。
- **Google Drive 配额耗尽返回 HTTP 200 + HTML**，`csv.DictReader` 读它得 0 行不报错，
  而 `0 % 12 == 0` 为真，常见校验会放行。
- **zsh 里 `GID` 是只读变量**，赋值报 `failed to change group ID`。
- **feed 与 OE 的位置名不同**（jungle/bottom/support vs jng/bot/sup），patch 格式也不同。
- **crosswalk 必须只用 `confidence == 'primary'`**，全表有 294 个一对多。

### 7.3 三条未过的判据：是判据的问题，不是模型的问题

这一节的参照分布**全部由开发集算出，不使用 holdout 的任何信息**，
且本项目**没有因为揭盲结果对模型做任何调整**。

从开发集样本外随机抽 989 场（与 holdout 同样大小）800 次：

| 指标 | holdout 实测 | 参照中位 | 5% | 95% | 实测分位 |
|---|---|---|---|---|---|
| ECE | 0.04647 | 0.04546 | 0.03271 | 0.06139 | **54%** |
| 校准斜率 | 1.07973 | 1.00973 | 0.85663 | 1.16133 | **78%** |
| Brier | 0.21457 | 0.21547 | 0.20776 | 0.22362 | **44%** |

三个都落在参照分布的正中央。

**这三条阈值是按全样本（23,060 场）的尺度定的，直接套到 989 场上不成立：**

| 预注册判据 | 参照分布里能满足它的子集比例 |
|---|---|
| ECE ≤ 0.03 | **1.9%** |
| Brier ∈ [0.216, 0.228] | 43.2% |
| 斜率 ∈ [0.93, 1.07] | 53.0% |

也就是说，即便模型完美无缺，ECE 这一条也有 98% 的概率过不了。

**这不是事后找补。** 揭盲脚本记录的 git sha 是 `437d1cb`，
正是 `reports/stage9_pre_reveal_check.md` 入库的那次提交——
ECE 的小样本正偏（全样本 0.0105 → 1,302 场子集期望 0.0402）
在揭盲之前就已经量化并写进报告。

**应当吸取的教训**：预注册指标区间时，必须按**实际评测样本量**定，
而不是按开发期的全样本尺度。ECE 尤其如此，它有随样本缩小而增大的系统性正偏。

### 7.4 最强的一条证据：holdout 与 walk-forward 几乎一致

| | log loss |
|---|---|
| walk-forward 样本外（23,060 场） | 0.61917 |
| **final holdout（989 场）** | **0.61653** |
| 差距 | **0.00264** |

手册 §8 阶段 9 验收①要求这个差距小于 0.02，实测只有 **0.00264**，
而且方向是 holdout **更好**。

这条比任何单个指标都重要：**它说明整个模型选择过程本身没有过拟合。**
开发期做了几十次比较、三轮预注册修订、七个候选模型，
最终在一次都没看过的数据上拿到了几乎相同的表现。

顺带一个验证：阶段 2 预测 holdout 期的 m̄ 是 2.7596，实测 **2.740**，误差 0.7%。

### 7.5 结论

**系统达成了设计目标。** 在 BP 结束、开赛前，对 tier-1 全部赛区与国际赛事
（含正在进行的 2026 世界赛）给出校准良好的胜率，
样本外 log loss 0.617，与真金白银的预测市场统计上无法区分。

**而项目的主要科学结论是一个负结果**：
BP 阶段本身（协同、克制、选手熟练度）在职业赛的数据量下贡献不可测量。
决定胜负的可预测部分，几乎全部来自队伍与选手的实力。
