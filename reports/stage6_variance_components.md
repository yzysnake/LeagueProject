## 0. 结论先行（七条，按重要性排）

1. **`k₁ = 476` 是错的。本数据上英雄层 `k = 774`**（两条独立路线给出 773.3 与 774.1，
   对应 σ = 0.017981 与 0.017972，**差 0.05%**）。收缩比现在强 **63%**，
   what-if 单次换英雄的 `Δp` 会因此再缩水约三分之一。
2. **手册的 player×champ「SD = 0.036–0.044、k = 129–193」在本数据上被否**。
   置换零分布校正后的矩估计是 **0，95% CI [0, 0.0190]**（即 `k ≥ 693`）；
   分层模型给 0.0017。而合成对照证明：**如果真有 0.04，这套工具测得出来**
   （注入 0.04 时读数 0.032，CI [0.024, 0.043]，与零分布完全分离）。
3. **队内选手偏差是真的，而且不小**：σ_player = 0.2006 logit
   [0.1877, 0.2129]，折合胜率 0.0501 → `k_player_within_team ≈ 99`。
   时间外推检验（训练 <2025-01-01，测试 4,403 场）里，加上选手层
   **样本外 log loss 从 0.67296 降到 0.65463（−0.01833）**——
   比阶段 4 实测的 L2→L3 增量 (+0.00160) 大 **11 倍**。
   **这不是"选手不重要"，这是现在那版 player Elo 没把信号取出来。**
4. **手册那三个参考值系统性偏高约 21%**：我的矩估计 / 手册 =
   player 0.81、team 0.79、champion 0.78、champion×position 0.79。
   四个层的比值几乎一模一样，说明不是随机差异，是口径差一档。
5. **队伍层与选手层的分离是脆弱的，而且在全 dev 口径下直接崩掉**：
   全 dev（94,338 场 / 10,394 选手 / 1,987 队伍）上 σ_team 塌到 **0.0011**，
   σ_player 涨到 0.2917——选手层把队伍层整个吃掉了。合成对照复现了同一个塌陷。
   **所以本报告的主口径必须是 tier≥1，全 dev 的 team/player 拆分不可用。**
6. mean-field SVI 对所有 σ 都**系统性低估**（合成恢复检验实测）。
   所以报出的每一个 σ 都是**保守下界**，`k` 都是**保守上界**。
7. **手册验收⑧给 SVI 定的「跨 seed `max|Δlogit| < 1e-3`」这条过不了，实测 0.474**
   （差 474 倍）。固定 seed 是逐位可复现的，跨 seed 的 σ 也只差 1.3–2.8%，
   但 38,088 个随机效应里单个实体的位置在不同局部最优之间能差 0.29 logit（p99）。
   本模块不上线所以不受影响，**但这条门禁对任何 SVI/BT 的 per-entity rating 都得重写**。
   见 §3.3。

## 1. 模型

```
logit P(blue win) = side_μ + σ_side·side_raw[league]
                  + 5·(team[blue] − team[red])
                  + Σ_blue dev − Σ_red dev
                  + Σ_blue champ − Σ_red champ
                  + Σ_blue pc − Σ_red pc

team[j]   = region[reg(j)] + σ_team·team_raw[j],  region = σ_region·region_raw
dev[i]    = σ_player·player_raw[i]     （选手相对**其所在队伍**的偏差）
champ[c]  = σ_champ·champ_raw[c]
pc[i,c]   = σ_pc·pc_raw[i,c]
σ_* ~ HalfNormal(0.5)，全部非中心参数化
```

按任务书的嵌套 `player_effect ~ N(team_effect, σ_player²)`：**5 名选手共享同一个
team_effect，所以队伍项在一侧 logit 里的系数是 5**。这一点必须记住，否则
σ_team 会被少读 5 倍。全部非中心化不是风格问题——中心化写法在 σ→0 处是漏斗形，
mean-field 会直接卡死在 σ≈0。

**红线 3（§6.1.2）归属**：手册 §4.1 把 `k` 归在「每个 fold 必须重估」。本模块的纪律是：

- SVI 分层模型只跑一次，**它的输出不进任何 fold 的拟合路径**，只是测量与报告；
- 生产里逐 fold 重估的是 `moment_variance_components(train_slice)`，
  23k 场上点估计耗时 **≈3 秒**（不含 bootstrap），满足 §4.1 的成本预算；
- 第 6 节实测了「逐 fold 重估」到底会让 `k` 动多少。

### 3.3 复现性：**同进程**内 bit-identical、**跨进程**不是、跨种子差 474 倍

手册验收⑧给 BT/SVI 这一支定的是 T2 档 B：「固定 seed bit-identical
**且**跨 seed `max|Δlogit| < 1e-3`」。**两半都测了，两半都要分情况说。**

**(a) 固定种子、同一进程内 —— bit-identical，过。**
同一个 python 进程里 `fit_svi(d, seed=0, steps=30_000)` 连跑两次，
30,000 步的 −ELBO 数组 `(l1 == l2).all() == True`，**30,000 步里 0 步不同**，
`max|Δ| = 0.0`；σ 也一模一样到 float32 全精度
（σ_player 两次都是 `0.19393184781074524`，σ_champ 都是 `0.07172000408172607`）。
函数本身没有未播种的随机源。

**(b) 固定种子、跨进程 —— 不是 bit-identical，这一半过不了。**
把 `main()` 在另一个进程整个重跑，落盘的 ELBO csv 里
**3,000 个格子有 1,772 个（59.1%）不同**，最大绝对差 0.01、
**最大相对差 1.98e−7**（≈ float32 在 1.5e4 处的 10 个 ulp）。
seed 0 的终值一次是 `15267.2705`、另一次是 `15267.2695`。

这不是 seed 的问题，是 **float32 + XLA CPU 归约顺序**的问题：
同一份计算图在不同进程里线程划分不同，浮点加法不结合，尾数最后几位就不一样。
**重要的是它不影响任何对外结论**：跨进程复跑后，
5 个种子的 σ 全部对到小数点后 6 位
（seed 0: player 0.193932 / team 0.060455 / champ 0.071720 / pc 0.007954），
池化后的 σ_player = 0.20060、σ_champ = 0.07192、σ_team = 0.06110、σ_pc = 0.00664
与 §2.1 表**逐位一致**，矩估计那一路是纯 numpy，完全 bit-identical。

> 所以「T2 档 A/B 的 bit-identical」这条门禁，**对任何跑在 XLA 上的 float32 模型
> 都必须写成"同进程内 bit-identical + 跨进程相对误差 < 1e−6"**，
> 否则门禁会在一台机器上过、换个负载就红，而模型其实没变。
> 要真 bit-identical 得开 `jax_enable_x64` 并锁死线程数，代价是慢一倍，不值得。

**(c) 跨种子 —— 差阈值 474 倍，这一半彻底过不了。**
用后验均值效应对全部 23,596 场算 logit，seed 0 vs seed 1
（`cross_seed_logit_stability(d, seeds=(0,1))`，这条门禁已收进模块，
不再是临时脚本）：

| 量 | 实测 | 门禁 |
|---|---|---|
| `max｜Δlogit｜` | **0.474017** | < 1e-3 ✗ |
| `p99｜Δlogit｜` | 0.291878 | — |
| 中位数 `｜Δlogit｜` | 0.068917 | — |
| 两个种子 logit 的相关 | 0.993821 | — |
| `max｜Δp｜` | **0.117937**（11.8 pp） | — |
| `mean｜Δp｜` | 0.017456（1.75 pp） | — |

**差阈值 474 倍，这条不可能过。** 原因不是没收敛（ELBO 尾段极差只有 1.2 nats），
而是 38,088 个随机效应里**大量个体是弱可识别的**：整体 logit 的相关达 0.994，
但单个实体落在哪里，不同的局部最优给出的答案能差 0.29（p99）。
对本模块无所谓（它只报 σ，σ 的跨种子 CV 只有 1.3–2.8%）；
但**谁要把 SVI/BT 的 per-entity rating 送进生产，`max|Δlogit| < 1e-3` 这条得重新定**，
要么改成"σ 层面的稳定性"，要么固定 seed 并把 seed 写进 artifact 指纹。

## 4. 与独立矩估计的交叉验证（验收④的判据）

### 4.1 我自己算的矩估计

DerSimonian–Laird / Kleinman 的 beta-binomial 矩估计：
`σ² = [Σnₑ(p̂ₑ−p̄)² − (E−1)p̄(1−p̄)] / [N − Σnₑ²/N]`，**必须扣掉二项噪声那一项**。
实体级 cluster bootstrap 300 次给 CI。胜率单位，与手册同口径。

| 层 | 单元数 | 观测数 | 中位/单元 | **σ** | 95% CI | **k** |
|---|---|---|---|---|---|---|
| team | 241 | 47,404 | 105 | 0.10474 | [0.09401, 0.11556] | 22.8 |
| player（边际） | 2,034 | 236,923 | 48 | 0.10500 | [0.10067, 0.10909] | 22.7 |
| **champion** | 171 | 237,020 | 976 | **0.01797** | [0.01449, 0.02071] | **774.1** |
| champion×position | 520 | 237,020 | 48.5 | 0.01927 | [0.01565, 0.02238] | 673.4 |
| **player×champion**（残差） | 35,719 | 236,923 | 3 | **0.0** | **[0, 0.01899]** | **∞（≥693）** |

player×champion 用的是**残差 + 置换零分布**（手册 §4.3 点名那个正偏必须扣）：
基准取 player-year 胜率，残差按 (player, champion) 聚合；再把 champion 标签
**在 player-year 内置换** 20 次得零分布。实测
`obs_var = −0.0040288`、`null_var_mean = −0.0038763`、`null_sd = 0.00014912`
→ 差值 `−0.00015`，即 **−1.02 个零分布 SD**。毫无信号。
（两个 var 都是负的，因为残差在 player-year 内恒和为零，会压低组间平方和——
这正是必须用置换零分布而不是解析式的原因。）

> ⚠️ **第一版的 bootstrap 是错的**：对选手重抽时被抽中两次的选手，他的两份拷贝
> 会并进同一个 (player,champ) 格子，格内方差不变而 n 翻倍，组间项被凭空放大，
> 点估计 0 也能 bootstrap 出 [0.115, 0.122]。修法是给每个副本加唯一后缀。

### 4.2 两条路线对表

| 层 | SVI（胜率单位） | 矩估计（胜率单位） | 比值 | <3 倍？ |
|---|---|---|---|---|
| **champion** | 0.01798 [0.01582, 0.02037] | 0.01797 [0.01449, 0.02071] | **1.001** | ✓ |
| **team（边际）** | 0.13552 [0.12836, 0.14278] | 0.10474 [0.09401, 0.11556] | **1.294** | ✓ |
| **player（边际）** | 0.13552（同上） | 0.10500 [0.10067, 0.10909] | **1.291** | ✓ |
| **player:champion** | 0.00166 [0.00074, 0.00405] | 0.0 [0, 0.01899] | 点估计落在矩估计 CI 内 | ✓ |

**验收④「差异 <3 倍」全部通过。** 两点说明：

- **team/player 的边际量必须这样对**：矩估计测到的「选手胜率离散度」
  其实就是他队伍的胜率离散度（这解释了手册里 player 0.1294 与 team 0.1330
  为什么几乎相等）。模型里对应的量是
  `0.25·√(25σ_team² + 5σ_player²)`——一支队面对平均对手时的胜率偏移 SD。
- **1.29 的方向可解释**：矩估计把每支队 7 年的胜率**平均成一个数**，
  队伍逐年的强弱起伏被洗掉了；而分层模型的选手层跟着转会走，
  能把这部分跨年变动捡回来。所以模型隐含值高于矩估计是预期方向。

| 层 | 手册 | 我的矩估计 | 比值 | 手册的 k | 我的 k |
|---|---|---|---|---|---|
| player | 0.1294 | 0.10500 | 0.81 | 14 | 22.7 |

**第五层不是量级差异，是定性推翻。**

## 5. 合成恢复检验：这把尺子准不准

用**真实的**索引结构（同样的 23,596 场、同样的队伍/选手/英雄出场表），
只把 y 换成模型自己按已知 σ 生成的，再跑同一套 SVI 看能不能读回来。
这是整份报告里最重要的一段——**没有它，上面所有 σ 都无法判断偏在哪边。**

| 真 σ_player | 真 σ_team | 真 σ_pc | 读到 σ_player | 读到 σ_team | 读到 σ_champ (真 0.07) | 读到 σ_pc |

## 6. 逐 fold 重估会让 k 动多少（红线 3 的经验依据）

矩估计沿扩张训练窗重算（`moment_stability_over_origins`）：

| origin | n_games | k_team | k_player | **k_champion** | k_champ×pos | k_player×champ |
|---|---|---|---|---|---|---|
| 2021-01-01 | 6,346 | 19.6 | 17.6 | 565.8 | 645.9 | 723.6 |
| 2022-01-01 | 9,676 | 20.1 | 19.0 | 678.8 | 688.7 | 115,060 |
| 2023-01-01 | 12,969 | 19.7 | 19.6 | 689.6 | 670.9 | ∞ |
| 2024-01-01 | 16,205 | 20.5 | 20.7 | 713.4 | 669.0 | ∞ |
| 2025-01-01 | 19,298 | 20.9 | 21.0 | 750.5 | 684.3 | ∞ |
| 2026-01-01 | 22,017 | 22.4 | 22.1 | 814.2 | 721.5 | ∞ |
| 2026-06-01 | 23,702 | 22.8 | 22.7 | 774.1 | 673.4 | ∞ |

`k_champion` 在 566–814 之间走，全距 **1.44 倍**；去掉最早那个只有 6 千场的窗口，
范围收到 679–814（1.20 倍）。`k_team` / `k_player` 全程 17.6–22.8。
**逐 fold 重估确实会动，但动的幅度（≤1.2 倍）远小于「476 → 774」这个错误（1.63 倍）。**
所以优先级很清楚：先把 476 改对，再谈要不要逐 fold 重估。

矩估计点估计在 23.7k 场上 ≈ 3 秒，逐 fold 重估的成本完全可以接受。

## 7. 负结果与不能下的结论

### 7.1 全 dev 口径下队伍层直接塌掉

`load_dev()` 全量（94,338 场 / 10,394 选手 / 1,987 队伍 / 162,710 个 pc 单元，
SVI wall 97 s）：

| 层 | tier≥1（主口径） | 全 dev | |
|---|---|---|---|
| σ_region | 0.1799 | 0.1638 | 稳 |
| σ_team | **0.0611** | **0.0011** | **塌了** |
| σ_player | 0.2006 | 0.2917 | 吃掉了队伍层 |
| σ_champ | 0.0719 | 0.0802 | 稳（k 622 vs 773） |
| σ_pc | 0.0066 | 0.0042 | 稳（都是零） |

10,394 个选手去解释 1,987 支队伍，5 人一组的和可以重构出任意队伍效应——
这正是第 5 节合成检验里 σ_player=0.30 那一行的塌陷，在真数据上复现了。
**所以 team/player 的拆分只在 tier≥1 口径下报，全 dev 的那两个数不可用。**
英雄层不受影响（它的单元密度是 976 场/英雄，跟选手层不共线）。

全 dev 的矩估计（n_boot=100）另有两处要如实记上：
`k_champion = 844`（tier≥1 是 774，动 1.09 倍），
而 **player×champion 残差在全 dev 上点估计不是 0 而是 σ = 0.0145（k = 1,189）**
—— 但它的 bootstrap 下界仍是 0（CI [0, 0.0218]），且仍远低于手册的 0.036–0.044。
所以"这一层没信号"的结论不变，但"点估计恰好为 0"是 tier≥1 口径下的巧合，
不要当成结构性事实去引用。

### 7.2 σ_player 是信号还是记住了训练集

单看层级模型的 σ 不足以回答——2,029 个选手 vs 240 支队伍，自由度差 8.5 倍。
所以做了严格向前的时间外推（训练 <2025-01-01 的 19,193 场，
测试 2025-01-01 起的 4,403 场，同一套静态效应、无时间衰减）：

| 变体 | 样本外 log loss | Δ | 样本外 Brier | 拟合出的 σ_player |
|---|---|---|---|---|
| 只有队伍层 | 0.67296 | — | 0.23955 | — |
| + 选手层 | **0.65463** | **−0.01833** | 0.23046 | 0.1696 |
| + 英雄层 | 0.65212 | −0.00251 | 0.22930 | 0.1714 |
| + 选手×英雄层 | 0.65216 | **+0.00004** | 0.22931 | 0.1713 |

**选手层在样本外净赚 0.0183 log loss，英雄层 0.0025，选手×英雄层 0.0000。**
三条的方向和量级，与阶段 4 的 L3→L4（champ_meta，+0.00159）和
§4.3 的"选手×英雄净增益≈0"完全一致，但选手层这一条差得很远：
阶段 4 实测 L2→L3 只有 +0.00160。

**必须说清楚这条对比的边界**：这里的队伍层是**静态**的（7 年一个数），
而 L2 的 team Elo 是在线递归的，本来就会跟着换人而漂移——
所以 0.0183 里有一部分是 Elo 已经拿到了的。
**不能直接说"player Elo 少拿了 0.017"。** 能说的是：
在一个队伍层不会随时间更新的模型里，选手身份还能再买到 0.0183，
而这个量级比整个 draft 层（0.0025）大一个数量级。
**"把功劳分配到个人"值得做，是本报告能给的最硬的一条方向性证据。**

### 7.3 其他不能下的结论

- **mean-field 的 95% CI 偏窄**。它不含 VI 自身的随机性；本报告报的是
  5 个种子池化后的 CI（已含跨种子散布），但 mean-field 忽略后验相关这一项
  仍然会让区间偏窄。真实区间比表里宽，宽多少没测。
- **模型没有时间维度**。所有效应是 7 年一个常数。选手层大概率吸收了一部分
  "队伍逐年强弱起伏"，这既是 §4.2 里 1.29 那个比值的来源，也是
  σ_player 不能直接当作"个人能力"读的原因。
- **没做 MCMC 对照**。手册 §5.4 明说 NUTS 在这个规模上跑不动，本报告照做，
  所以"SVI 近似有多差"只有合成恢复检验一条证据，没有金标准对照。
- **σ_region = 0.1799（一侧 logit 0.90）看着大**，但它同时吸收了赛区实力差
  和跨赛区交手样本太少（国际赛只占 1,698 场）带来的不确定性，不建议单独引用。

## 8. 落盘：`configs/shrinkage_constants.yaml`

**`k` 取矩估计不取 SVI**，理由：矩估计能逐 fold 秒级重估（§4.1 的硬要求），
而 SVI 是 mean-field 近似且只跑一次全段。SVI 的数字同时存进文件，
作为"两条独立路线同量级"的存档证据。唯一只有 SVI 能给的
`player_within_team` 单独放在 `svi_only` 段——矩估计测不到它，
因为一个选手的胜率就是他队伍的胜率。

文件里 `k:` 段的实际内容（本次复跑落盘，3,010 字节）：

```yaml
k:
  team: 23
  player: 23
  champion: 774
  champion:position: 673
  player:champion: null        # σ 点估计为 0 → k→∞ → 完全收缩到先验 = 这一层不要
  player_within_team: 99       # 只有分层模型能给，矩估计测不到
```

同一份文件里还存了 `moment`（五层的 σ、CI、单元数）、`svi_logit`（四层的 logit 后验
与换算后的胜率单位）、`crosscheck_team_marginal`（SVI 隐含 0.135518 vs 矩估计
0.104742，比值 **1.294**，即验收④的"<3 倍"判据存档）以及 `meta`（口径、
holdout 截止线 `2026-06-01`、种子、总 wall 187.7 s）。

> ⚠️ **这个文件之前是 0 字节，而且崩得无声无息。** 首轮 `main()` 走到最后一步
> `yaml.safe_dump(doc, fh)` 时被 `np.float64(22.8)` 抛 `RepresenterError`——
> 但 `open(path,"w")` 已经先把文件截成 0 字节了，于是 traceback 滚过去之后
> 留下一个"存在但是空"的 config。两处都修了：
> `_plain()` 在出口把 numpy 标量统一降级成 python 标量；
> `write_shrinkage_yaml()` 改成**先序列化成字符串、成功了再落盘**。
> 教训值得记：`yaml.safe_dump(obj, file_handle)` 在失败路径上会留下空文件。

复现（约 3.5 分钟：5 × 30k 步 SVI 187.7 s + 矩估计与 bootstrap 13 s）：


## 9. 对下游的三条具体影响

1. **`draft_priors.py` 的 `k₁` 应从 476 改到 774**（champion×position 那一支改到 673）。
