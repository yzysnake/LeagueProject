## 1. Primary comparison（唯一一个）

```
M_main(全特征)  vs  L3(side_prior + team rating + player rating)
```

- 指标：**log loss**
- 样本：tier-1 + 国际赛子集的 walk-forward OOS
- 检验：series 级 block bootstrap + Diebold-Mariano（Harvey 小样本修正）
- 其余所有比较一律标记 **exploratory**，用 Benjamini-Hochberg FDR 控制

## 2. 成功判据

- (a) walk-forward Brier ≤ 0.228 且 calibration slope ∈ [0.93, 1.07]
- (b) draft 特征组相对无 draft 基线的配对 ΔlogLoss ≥ 0.004，
  且在 series 级聚类下 |t| > 2.5，且**连续两个留出期同号**

## 3. 失败判据（红线，CI 自动 fail）

```
任一 fold AUC > 0.78   或   全样本 accuracy > 67%   或   log loss < 0.60
```

触及任一条 → 强制走完 PLAN.md §6.9 的泄漏自查清单，结论写进报告，不得跳过。

参照实测：随机划分 + 整赛季聚合胜率会把 AUC 从诚实的 0.650 推到 0.794。
红线抓的就是这种。

## A3 · 替换失效的 fold 级 AUC 红线（2026-09-20）

**合法性前提**：`models/` 下只有 prod.json（阶段 5 的 L4 artifact），
**holdout 仍然一次都没有被加载过**（`load_holdout()` 默认抛异常，
全仓无任何地方设置 `LOLWP_ALLOW_HOLDOUT`）。修订时 HEAD = `947523bb2ca7faef318da6053e6a6ec9a7398047`。
本修订的依据是**模拟**，不是"模型过不过"。

### 原判据

§3 失败判据写的是：`任一 fold AUC > 0.78`（与 accuracy > 67%、log loss < 0.60 并列）。

### 它为什么是坏的

**问题一：小折使它在零信号下也必然触发。**
90 折里有 8 折的验证段不足 50 场，最小的只有 **3 场**。3 场的 AUC 只能是 0 或 1。
用纯随机预测（真实 AUC 恒为 0.5）跑 400 次模拟：

| 量 | 值 |
|---|---|
| 最大 fold AUC 中位数 | **1.0000** |
| P(最大 fold AUC > 0.78) | **63.0%** |
| 只看 ≥200 场的折时的超线概率 | 0.0% |

**问题二：即便限制到 ≥200 场，对一个表现正常的模型仍有高误报。**
以模型自身水平（总体 AUC 0.7148）与实测折大小为参照分布，模拟 2000 次：

| 量 | 值 |
|---|---|
| 最大 fold AUC 中位数 | 0.7753 |
| 95 分位 | 0.8055 |
| **P(最大值 > 0.78)** | **38.4%** |

也就是说：一个完全健康的模型，有 38% 的概率触发这条"泄漏"红线。
**一条 38% 时间在报警的告警器等于没有告警器**——它只会被人忽略。

### 实测现状（供审计）

BT4 的逐折 AUC：全部 90 折最大 **0.8750**（fold 10，仅 **18 场**）；
限制 ≥200 场的 48 折最大 **0.7805**（fold 61，490 场，2024-01-21）。
0.7805 落在上述参照分布的 **63 分位**，P(最大值 ≥ 0.7805) = **37%**，
属正常波动，不是泄漏信号。

### 替换为

```
失败判据（红线）修订后：
  1. 全样本 accuracy > 67%                      （不变）
  2. 全样本 log loss < 0.60                     （不变）
  3. 【替换】全样本合并 AUC > 0.78               ← 原「任一 fold」改为「合并」
  4. 【新增】最大 fold AUC（仅计 n >= 200 的折）
     超过「以模型自身合并 AUC 与实测折大小为参照、2000 次模拟得到的 99 分位」
```

第 3 条用合并 AUC：它是真正关心的量，且不受小折噪声影响。
第 4 条保留逐折检查的用意（抓"某一段时间突然特别准"），
但把阈值从一个拍脑袋的常数改成由模拟给出的参照分位数。

**BT4 在修订后的红线下全部通过**：
accuracy 0.6567 < 0.67，log loss 0.6165 > 0.60，合并 AUC 0.7148 < 0.78，
最大大折 AUC 0.7805 < 参照 99 分位 0.8191。

# 揭盲之后的修订

## A4 · 生产模型改用全量数据重训（2026-10-24，使用者要求）

**合法性前提**：final holdout 已于 2026-09-20 一次性揭盲（`437d1cb`，记录见上一节与
`reports/final_holdout_result.json`）。本修订**不是**基于揭盲结果的模型调整：
模型规格一律不动——`PROD_FEATURES`、分层 BT 与两个状态机的超参、外层 L2 logistic（C = 1.0）
都和揭盲时评测的那个模型一模一样，**只把训练数据的截止时间从 2026-05-31 往后延到最新**。

### 为什么

生产模型的队伍与选手实力停在 2026-05-31：夏季赛、MSI、各赛区季后赛与世界赛资格赛的
三个半月它都不知道。10 月盯盘预测世界赛，用的是一份过时了近五个月的实力表。
holdout 揭盲之后，留着这段数据不用已经换不来任何东西——它只能被评测一次，而这一次已经用掉了。

### 做法

- `features.loader.load_all()`：全量数据的唯一入口，**揭盲记录不在时拒绝**（揭盲之前这样用就是泄漏）。
- `models.artifact.train(scope="all")` 为默认的生产口径；`--scope dev` 仍能原样重建揭盲时评测的模型。
  artifact 的 `meta.data_scope` 写明口径，`refit_note` 写明两个历史成绩不属于全量模型。
- 实时链路的降级评分与 artifact 同一口径（dev 配 `load_dev()`，all 配 `load_all()`）。
- 盯盘台账每条预测记下是哪个模型算的（`model: "BT4_LR@训练截止日"`），新旧模型的预测分得开。
- **评测基础设施不动**：walk-forward、上线门禁、被搁置假设的重测仍然只走 `load_dev()`，
  数字与揭盲前可比。

### 对估计的影响（按上一节「对未来的约束」明确标注）

- **0.61653 仍是 dev 口径模型（训练截至 2026-05-31）的无偏样本外估计**，报告里的数字不变。
- 它**不是**全量模型的估计：全量模型在 holdout 期是样本内的，
  **对全量模型而言，该估计已不再是无偏的样本外估计**，也不得再拿 holdout 评它。
- 全量模型的样本外成绩只看盯盘台账里、**训练截止日之后**落盘的预测（按 `model` 字段筛）。

`scripts/day0_fetch.sh` 原来「文件已存在就跳过」，而 OE 每天更新的是 Drive 上**同一个**文件，
所以 2026-09-19 之后 `make data` 再没拿到过新比赛（数据停在 9/18）。已改为当年文件每次重下。
10/24 当天重下撞上 Drive 配额（HTTP 200 + 配额错误页，脚本按设计保留旧文件），

## A5 · 数据修正：世界赛资格赛归回所属赛区（2026-10-24）

**问题**：OE 的 league code `WLDs` 里不只有世界赛主赛事，还混着各赛区内部的世界赛资格赛——
LPL 每年（2022–2026，gameid 是 LPL 官网格式、url 指向 lpl.qq.com）、LCK 2022–2024，共 **98 场**。
它们是一个赛区内部的比赛，按本项目自己的 tier 定义（tier 2 = 参赛队来自 ≥3 个赛区）不是国际赛，
却被记成了 tier 2 的「全球总决赛」。使用者在「历史回看」里筛全球总决赛时发现了 2026-09-17/18 的
TES vs IG、WE vs JDG。

**修正**（`store.silver.reassign_worlds_qualifiers`）：逐年以当年第一场跨赛区的 WLDs 比赛为主赛事起点，
在那之前、两队所属赛区都已知且相同的 WLDs 比赛归回该赛区（league_canon、league_tier 随之改为
该赛区的值，league_raw 保留 OE 原值）。实测归回 98 场：LPL 60、LCK 38，全部 tier 2 → tier 1。

**对已有结论的影响**：
- 98 场原本就在 tier ≥ 1 里，训练与评测的样本**一场不多一场不少**；holdout 仍是 989 场。
- 唯一受影响的模型输入是按赛区收缩的蓝方先验（side_prior）：这些比赛从 WLDs 的池子挪到 LPL / LCK。
  side_prior 的标准化系数只有 0.014，量级可忽略。
- 归档的 walk-forward 与 holdout 数字是修正前算的，**不重算、不改写**；之后重跑会有极小的差异，
  `make reproduce` 会把它显式列出来。生产模型已按修正后的数据重训（仍为修订 A4 的全量口径）。


## A6 · 分层 BT 的训练标签改用赛后经济差的软标签（2026-10-25，使用者要求）

**改什么**：生产模型（全量口径）的分层 BT 快照，似然里的 y 从「蓝方胜 / 负」换成

    y_margin = σ(0.5 · Δ)，Δ = 终局（蓝 − 红）总经济 ÷ 时长，单位「千金 / 10 分钟」

（`models/margin.py`）。外层五个特征、两个状态机、外层 L2 logistic 一律不动；`--scope dev` 仍是胜负标签，
原样复现揭盲时评测的模型。缺终局经济或时长的局（silver 里 0.1%）退回胜负标签。

**为什么合法**：§4.8.1 的白名单禁的是**本局**的赛后统计进**本局**特征——那确实是泄漏。这里用的是
**已经打完的历史局**的赛后统计，而且只当快照的训练标签：快照 `as_of` 只吃开赛早于它的比赛，
任何一局的经济差都进不了开赛不晚于它的那些局的特征，和胜负标签 `y` 进 BT 是同一条路径。落实为：

- bronze 照旧物理不含赛后统计列；两列（`totalgold` / `gamelength`）在白名单里单列为 `rating_label`，
  由 `store/margins.py` 从原始 CSV 单独读出，存成 `data/silver/margins.parquet`，从不并进特征表；
- `tests/test_hier_bt.py::test_future_soft_label_perturbation_invariance`：只改 T 之后各局的软标签，
  T 之前的特征逐位不变（档 A，与胜负标签的那条同一标准）；
- 台账里盯盘补充的局同样只用已结束局的 feed 终局帧（对账时记下），不读进行中的任何帧。

**怎么选出来的**（`reports/exp_model_improvements.md` §2，复现：`scripts/exp_margin_bt.py`）：
调参段（2016–2018，walk-forward 9,145 场）在 5 组 (λ, κ) × 2 种接法（替换胜负 / 与胜负并列）里选，
λ 是软标签与胜负的混合比例。调参段最好的是 **λ=1、κ=0.5、替换**——也是最简单的改法。
在验收段（2019 起，23,060 场，与调参段不重叠）确认：

| 段 | Δ log loss | MDE | 余量 | t | 两半 |
|---|---|---|---|---|---|
| 调参 2016–2018 | +0.00389 | 0.00256 | 1.52× | 4.26 | +0.00422 / +0.00356 |
| 验收 2019 起 | +0.00390 | 0.00128 | 3.04× | 8.51 | +0.00405 / +0.00376 |

§6.7 三条两段都过。**多重比较的交代**：10 个组合在验收段上也都看过（探索性）；除 κ=1 外，
λ ≥ 0.75 或并列接法的 6 组在验收段相差 ≤ 0.0009、余量全部在 2.5× 及以上，选择效应可以忽略。
同一轮研究里 15 分钟经济差做标签（xW15）在 λ ≥ 0.75 时更差，没有采用。

**对估计的影响（按「对未来的约束」明确标注）**：

- 本修订在揭盲之后做出，但**选择过程只用了开发期数据**（`load_dev()`），holdout 没有参与、也不再参与。
- 0.61653 仍是 dev 口径（胜负标签、训练截至 2026-05-31）模型的无偏样本外估计；
  **软标签模型没有 holdout 估计**。它在开发期的 walk-forward 是 0.61259（胜负标签同口径 0.61650）。
- 软标签模型自己的样本外成绩只看盯盘台账（预测在赛果之前落盘；每条记 `model` 与 `ratings`），
  以及 OE 恢复之后对 2026-09-18 之后比赛的一次性前瞻评估（规格从本修订起冻结）。
